# Outside-user validation protocol

Actual outside-user testing requires recruiting participants; it cannot be claimed from automated browser checks. Use three to five developers unfamiliar with Pyro. Give them a disposable workspace, a defined credit budget, and the support-assistant example. Do not coach them until they are blocked.

Ask each participant to create and save a policy, leave and reopen it, test a legitimate complaint and a privacy request, save a disagreement, run an evaluation, inspect the deciding check, adjust a draft, compare outcomes, connect the example application, and find the credits consumed and current plan limits.

Record time to first useful result, abandoned steps, unprompted questions, unexpected decisions, and whether the participant can explain Allow/Review/Block, publishing, input retention, monthly limits and prepaid credits. Ask what they would replace with Pyro and what would prevent adoption. Do not infer willingness to pay from compliments about the design.

Success targets for the next iteration: no lost work; a first correct integration without founder intervention; every billed test discoverable by source; participants can identify a false positive, reproduce it and compare a revised policy. Document actual observations separately from these targets.
